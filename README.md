# OMHP Publisher(WIP)

Проект собирает статический OMHP-хост из JSON-каталога и файлов, а также позволяет выложить его на S3. Для сборки нужен Node.js 20+, для загрузки — настроенный AWS CLI.

## Сборка

Запустите из корня проекта:

```sh
node omhp-publisher/cli.mjs build host/catalog.json ./omhp-dist https://media.example.org
```

Укажите фактический адрес, по которому клиенты будут читать хост. Каталог вывода должен быть новым. В результате появятся `index.html` с JSON-описанием хоста, `mediamap` со списком относительных путей, метаданные по маршрутам `image/<id>`, `video/<id>`, `author/<id>`, `thread/<id>`, `composition/<id>` и файлы в `media/`. Метаданные хранятся без расширения, чтобы URL соответствовали маршрутам OMHP.

Формат входа совпадает с [каталогом локального хоста](../host/catalog.json). Группы записей задаются массивами по типам, а необязательное поле верхнего уровня `name` задаёт имя хоста. Параметры записей:

- `image` — `id`, `title`, массив `files`.
- `video` — `id`, `title`, `file`, `type` (`h256` для MP4 с H.264 или `VP9` для WebM с VP9). Сборка копирует готовые файлы.
- `author` — `id`, `name`.
- `thread` — `id`, `text` и ссылка `theme` на обсуждаемую запись. Поддерживаются самостоятельные треды без `theme`, как в локальном хосте.
- `composition` — `id` и готовые поля метаданных OMHP.

Пути к файлам задаются относительно JSON-каталога. Для локальных записей используйте ссылки вида `/author/name` или `/video/demo` в полях `authors` и `theme`. Сборка проверяет их и подставляет адрес публикации. Ссылки на записи существующего демохоста на портах 8080 и 8081 тоже переносятся на адрес публикации. Внешние HTTP(S)-ссылки сохраняются.

## Загрузка

```sh
AWS_PROFILE=my-profile node omhp-publisher/cli.mjs upload ./omhp-dist s3://my-bucket --dry-run
AWS_PROFILE=my-profile node omhp-publisher/cli.mjs upload ./omhp-dist s3://my-bucket
```

Загрузчик задаёт Content-Type каждого объекта и публикует `mediamap` после файлов и метаданных. Объекты с совпадающими ключами обновляются. Удалённые из каталога записи исчезают из карты, а старые объекты остаются в бакете. См. [параметры AWS CLI](https://docs.aws.amazon.com/cli/latest/reference/s3/cp.html).

Для чтения OMHP настройте раздачу бакета или CDN. Запрос `/` должен отдавать `index.html` как JSON, а `/mediamap` и остальные пути — соответствующие ключи. Если загрузка идёт в `s3://my-bucket/some-prefix`, настройте `some-prefix` как корень публичного адреса. Для клиентов, обращающихся с другого origin, разрешите GET и HEAD через CORS на стороне раздачи.

## Интерфейс

Из корня проекта запустите `node omhp-publisher/cli.mjs ui`.
Откроется локальная страница в браузере. Относительные пути считаются от
каталога, из которого запущена команда. Доступны сборка, проверка загрузки
без записи в S3 и загрузка с выбранным профилем AWS CLI. Вывод команд
появляется в журнале. Ctrl+C в терминале завершает локальный интерфейс.

## Добавление записей

Формы в интерфейсе и команды ниже дописывают записи в существующий каталог.
Медиафайлы должны быть внутри папки каталога. Пути к ним указываются
относительно этой папки. У треда можно опустить последний аргумент.

```sh
node omhp-publisher/cli.mjs addImage host/catalog.json logo-copy 'Логотип' data-logo.svg
node omhp-publisher/cli.mjs addVideo host/catalog.json demo-copy 'Ролик' media/demo.mp4 h256
node omhp-publisher/cli.mjs addThread host/catalog.json demo-note 'Комментарий' /video/demo
```

По умолчанию интерфейс открывает формы с путём
`decorator-portfolio/catalog.json`. В этом каталоге четыре проекта из
«Компании декораторов» со ссылками на фотографии портфолио.

В браузере нажмите «Добавить запись», выберите тип и нужные файлы. Интерфейс
берёт каталог из поля «JSON-каталог» и копирует выбранные файлы рядом с ним.
Для видео тип определяется по расширению: MP4 или WebM. Размер одного запроса
ограничен 256 МБ.
